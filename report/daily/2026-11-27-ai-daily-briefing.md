## 1. 국산 NPU AIDC, K-Perf 기반 400Gb/s 풀스택 성능검증 추진

![K-Perf 국산 AI 반도체 성능평가](https://biz.chosun.com/resizer/v2/QTN74YBFNVK3XCF2RPA6YJPQWQ.JPG?auth=74b98b37bbdd7c362c753fbf547f34470d5c00dc981d1e27479b2f43d3115c16&height=630&smart=true&width=1200)

### 주요 내용

- 글루시스·아이에이클라우드·포인투테크놀로지·한국정보통신기술협회(TTA)가 K-Perf 기반 국산 AI 반도체 인프라 성능검증 업무협약 체결.
- TTA 판교 테스트베드의 국산 NPU 서버 기반 프라이빗 클라우드에 고성능 AI 스토리지와 400Gb/s급 인터커넥트를 결합하고, Cloud:iA·Gen:iA 플랫폼으로 이기종 자원 관리와 추론 워크로드를 운영할 계획.
- K-Perf 추론지표뿐 아니라 스토리지 I/O, 네트워크 연결 신뢰성, 전력효율, 운영 안정성을 함께 검증하며 TTA가 시험방법 자문과 결과의 중립적 분석 담당.

### 중요성

- 국산 NPU 평가가 칩 단독 연산성능에서 서버·스토리지·네트워크·오케스트레이션을 포함한 실제 서비스 수준의 풀스택 검증으로 확장되는 변화.
- 동일 NPU라도 데이터 공급과 자원관리 병목에 따라 추론 성능이 달라지는 만큼, 수요기관이 AIDC 도입 여부를 판단할 수 있는 현실적 비교자료 확보 가능.
- 아직 업무협약과 시험계획 단계로 성능·전력효율 결과는 공개되지 않았으며, 상용 경쟁력 관련 전망은 참여기업의 주장임.

### 시사점

- 공공 AI 컴퓨팅 조달에서 TOPS·메모리 용량뿐 아니라 TTFT, 처리량, 동시사용자 수, 에너지당 토큰, 장애복구시간을 포함한 서비스 수준 평가 필요.
- 국산 NPU와 GPU가 혼재하는 환경을 고려해 모델별 스케줄링·동적 배치·관측성·장애 전환을 K-Perf 후속 항목으로 확대할 필요.
- 검증 보고서를 재현 가능한 구성정보와 함께 공개해 공공·금융·제조 수요기관이 국산 가속기 도입 위험을 비교할 수 있도록 지원 필요.

## 2. Kioxia·NVIDIA, SSD로 GPU 유효 메모리 1PB 이상 확장 실증

![Kioxia와 NVIDIA의 AI 클러스터 SSD](https://static.tweaktown.com/news/1/0/107700_70_nvidia-rumored-to-team-with-kioxia-make-new-ssds-that-are-100x-faster-for-ai-workloads_full.jpg)

### 주요 내용

- Kioxia와 NVIDIA가 NVIDIA SCADA·Storage-Next 소프트웨어와 NVMe SSD를 결합해 GPU 유효 메모리 공간을 1PB 이상으로 확장하는 개념검증 결과 발표.
- NVIDIA GB200 NVL72 1개 랙의 18개 서버 노드에 KIOXIA XD8 7.68TB E1.S SSD 144개를 탑재해 약 1.1PB 원시용량 구성.
- 노드당 약 60TB의 플래시 확장 메모리와 512바이트 단위 접근을 이용해 최대 2조 개의 512바이트 벡터를 처리할 잠재력을 확인했다는 양사 발표.

### 중요성

- HBM에 모든 벡터·그래프 데이터를 적재하지 않고 SSD를 계층형 GPU 메모리로 활용해 대규모 RAG·벡터DB·그래프신경망의 데이터 크기 한계를 완화하는 접근.
- 고가 HBM 증설 대신 고성능 플래시를 활용하면 GPU 유휴시간과 데이터 분할·재적재 비용을 줄일 가능성이 있으나, 지연시간·처리량·내구성의 실제 비교값은 미공개.
- 1PB와 2조 벡터는 Kioxia·NVIDIA의 개념검증 구성 및 잠재 처리규모로, 상용 서비스의 보장 성능이나 비용절감 수치가 아님.

### 시사점

- 국내 메모리·SSD·스토리지 기업은 HBM과 경쟁하는 관점보다 CXL·NVMe·GPU 직접접근을 결합한 계층형 추론 메모리 시장을 공동 공략할 필요.
- 국가 AI 컴퓨팅센터의 장문맥·RAG 워크로드를 대상으로 HBM 단독 구성과 SSD 확장 구성의 토큰당 비용·전력·지연시간 비교 실증 필요.
- 대규모 벡터DB 조달 시 용량뿐 아니라 512바이트 소규모 랜덤 접근, 캐시 적중률, 장애복구 및 SSD 수명까지 성능평가 항목에 포함할 필요.

### 발행일 및 출처

- 미국 법인 최초 발표 2026년 11월 25일(미국 태평양시간), 일본 본사 발표 2026년 11월 26일(일본시간).

## 3. AWS, 장기 실행 AI 워크플로용 Lambda MicroVM 오케스트레이션 공개

![AWS Lambda MicroVM 실행환경](https://miro.medium.com/v2/resize%3Afit%3A1400/1%2AqSLhOYuf5ftCWvV_BGRfwQ.png)

### 주요 내용

- AWS가 Lambda durable functions에서 Lambda MicroVM의 생성·실행·수명주기를 관리하는 확장기능을 개발자 미리보기로 공개.
- durable functions는 최장 1년간 실행되는 다단계 AI 워크플로에 체크포인트와 자동 재시도를 제공하며, MicroVM은 VM급 격리·상태 보존·빠른 시작과 재개 지원.
- 단일 워크플로가 여러 MicroVM을 병렬로 오케스트레이션할 수 있고 SQS·EventBridge 이벤트로 실행 가능하며, TypeScript와 Python SDK·선택형 워커 라이브러리 제공.

### 중요성

- 에이전트가 생성한 미신뢰 코드를 단기 컨테이너가 아니라 상태가 유지되는 격리 VM에서 실행하면서 장시간 작업의 재시도·복구까지 관리하는 런타임 계층의 진전.
- 소프트웨어 팩토리, 보안 스캐너, CI/CD 등에서 모델 추론과 도구 실행을 분리하고 작업별 격리경계를 자동 생성할 수 있어 에이전틱 인프라의 운영 복잡도 감소 가능.
- 개발자 미리보기 단계로 기능 변경 가능성이 있으며 AWS도 운영환경 사용을 권고하지 않아 안정성·가격·콜드스타트 효과의 추가 검증 필요.

### 시사점

- 국내 클라우드·공공 AX 플랫폼도 에이전트별 격리, 상태 체크포인트, 재시도, 네트워크 허용목록, 실행 종료 후 폐기를 공통 런타임 기능으로 제공할 필요.
- 공공망 적용을 위해 MicroVM 이미지 공급망, 실행코드 서명, 비밀정보 주입, 도구별 최소권한과 감사로그 기준 마련 필요.
- GPU 추론 서비스와 CPU 기반 도구실행 환경을 분리해 비용을 줄이되, 전체 작업 추적 ID로 모델 호출·코드 실행·외부 API 행동을 연결하는 관측성 확보 필요.

## 4. OpenAI, 기밀 컴퓨팅 기반 ‘Private Inference’ 고객 시험 개시

![OpenAI Private Intelligence 발표](https://cdnx.premiumread.com/?f=jpg&q=100&t=6&url=https%3A%2F%2Fwww.malaymail.com%2Fmalaymail%2Fuploads%2Fimages%2F2026%2F09%2F30%2F365446.jpg&w=1000)

### 주요 내용

- OpenAI가 기업용 Private Intelligence의 일부인 Private Inference를 소수 고객과 시험하기 시작했다고 11월 25일 발표.
- Private Inference는 기밀 컴퓨팅과 검증 가능한 통제를 결합해 모델 처리 중 프롬프트와 응답을 보호하는 알파 기능으로 소개.
- Zero Data Retention과 Private Safety Processing을 함께 제공해 대상 API 워크플로의 입력·출력을 보관하지 않고, OpenAI 직원의 원문 접근 없이 자동 안전검토를 수행한다는 회사 설명.

### 중요성

- 저장·전송 구간 암호화를 넘어 모델이 데이터를 처리하는 사용 중 데이터 보호가 상용 프런티어 모델 도입의 핵심 경쟁요소로 부상.
- 금융·의료·국방·연구개발 등 민감정보 때문에 외부 모델 사용을 제한했던 조직의 도입 범위를 넓힐 가능성.
- 시험 고객, 지원 모델·지역·성능 영향·가격 및 독립 검증 결과는 공개되지 않았으며, 보호 효과는 현재 OpenAI의 제품 설명 기준.

### 시사점

- 국내 공공·금융 AI 조달은 기밀 컴퓨팅 여부뿐 아니라 하드웨어 원격증명, 키 소유권, 운영자 접근 차단, 로그·백업의 데이터 잔존 여부를 검증할 필요.
- 국산 클라우드와 NPU 환경에서도 TEE 기반 추론, 고객관리형 키, 외부 감사가 가능한 증명서 체계를 묶은 주권형 기밀추론 서비스 개발 필요.
- 민감정보 활용 확대 전에 처리 중 메모리 노출, 출력 재식별, 안전검토와 개인정보 최소수집 간 충돌을 포함한 공격·감사 시나리오 실증 필요.

- 과학기술정보통신부와 정보통신정책연구원이 기술·규범, 상생·혁신, 사회·신뢰 3개 분과의 위원 40명과 연구반 전문가 18명이 논의한 AI 사회정책 제언 공개.
- 학습데이터 목록 보유→권리자 포함 여부 확인→분쟁 시 제한적 공개의 단계적 저작권 보호와, 생성·유통·구제 전 과정을 포괄하는 AI 관여도별 차등 표시 제안.
- AI 자동화를 막기보다 고용구조 변화의 속도와 방향을 관리하는 단계별 정책, 서비스 위험과 특성에 따라 청소년 안전조치 수준을 달리하는 비례적 보호 제안.

### 중요성

- AI 기본법 시행 이후의 사회정책이 일률적 표시·금지보다 위험·관여도·서비스 이용자에 비례한 적응형 규율로 구체화되는 흐름.
- 학습데이터 목록의 전면 공개와 영업비밀 보호 사이에 보유·확인·분쟁 시 공개라는 중간 절차를 제시해 저작권 갈등 조정의 현실적 대안 제시.
- 이번 내용은 포럼의 정책 제언으로 정부 확정안이 아니며, 법률상 의무·집행기관·적용시점은 후속 정책 검토 대상.

### 시사점

- 학습데이터 추적성 제도 설계 시 원문 URL·권리상태·수집근거·제외요청 처리기록을 표준 메타데이터로 정의하고 독립 검증 절차 마련 필요.
- AI 생성물 표시는 이진 라벨보다 생성·편집·검수 단계의 인간 관여도와 고위험 용도를 함께 표시하는 기계판독형 체계 검토 필요.
- 고용·청소년 정책은 직종별 업무변화와 연령별 이용행태 데이터를 지속 수집해 훈련지원·안전기능의 강도를 조정하는 적응형 거버넌스로 운영할 필요.

## 7. 미국 칩·해외 컴퓨트 규제, 중국 AI 모델 출시 지연으로 현실화

![중국 Moonshot AI](https://nextomoro.com/content/images/2026/04/moonshot-ai.png)

### 주요 내용

- Reuters가 미국의 해외 데이터센터 컴퓨트 규제와 AI 기업의 무단 증류 차단 강화로 Z.AI의 약 3조 매개변수 GLM-5.5 출시가 2027년 1분기 이후로 밀릴 수 있다고 신규 보도.
- Moonshot AI는 해외 컴퓨트 접근이 차단되면 주요 모델 개발주기가 기존 6개월에서 12개월 이상으로 늘고 Kimi K4가 2027년 중반까지 지연될 수 있다고 내부 예상한 것으로 보도.
- 11월 19일 발효된 미국 상무부 규정은 해외 데이터센터에서 H100 약 750개 상당을 넘는 컴퓨팅을 중국 등 규제대상 기업에 제공할 때 허가를 요구하고, 기존 사업자에는 90일의 허가 취득기간 부여.

### 중요성

- 규제의 초점이 첨단칩의 물리적 수출에서 제3국 데이터센터를 통한 원격 연산 접근까지 확대되면서 중국 AI 기업의 저비용·고속 모델 개발방식에 직접 영향.
- OpenAI·Anthropic의 무단 증류 탐지·차단과 컴퓨트 통제가 결합해 모델 가중치·데이터·연산 접근이 동시에 전략적 통제대상으로 변화.
- 모델 일정과 개발주기 전망은 익명 관계자 취재에 근거하며 Z.AI·Moonshot이 확인하지 않은 내용이 포함돼 확정 일정이 아닌 위험 신호로 해석할 필요.

### 시사점

- 한국 클라우드·데이터센터는 고객의 최종 모회사, 원격접속 주체, 가속기 규모와 워크로드를 확인하는 수출통제 실사·로그보존 체계를 강화할 필요.
- 국산 NPU의 해외사업은 미국산 설계도구·메모리·네트워크·서버 구성요소의 재수출 규정 적용 여부를 서비스 계약 단계부터 검토할 필요.
- 중국 모델 공급 지연 가능성에 대비해 공공·기업 시스템은 특정 해외 모델 의존을 줄이고 복수 모델 라우팅, 국산 모델 대체시험, 데이터·프롬프트 이동성 확보 필요.
